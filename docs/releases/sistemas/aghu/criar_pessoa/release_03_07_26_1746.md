**Data:** 2026-07-03

**O que mudou:**
- `ui_criar_pessoa_aghu.py` adicionou o import de `executar_cadastro_pessoas` para permitir processamento de mais de uma pessoa na execucao manual.
- `ui_criar_pessoa_aghu.py` adicionou `MAX_PESSOAS_MANUAIS = 5` e separou `CAMPOS_PESSOA` em `CAMPOS_PESSOA_ESQUERDA` e `CAMPOS_PESSOA_DIREITA`.
- `AghuCadastroPessoaApp.__init__` deixou de inicializar `var_sexo`, `segment_sexo` e `entries_individual`, passando a usar `linhas_pessoas_individual`.
- `_criar_campos_individual` passou a renderizar uma lista dinamica de pessoas, com frame de linhas, botao `+ Adicionar pessoa` e mensagem de limite atingido.
- Foram adicionados os metodos `_criar_coluna_campos_pessoa`, `_preencher_coluna_campos_pessoa`, `adicionar_linha_pessoa`, `remover_linha_pessoa` e `_atualizar_estado_lista_pessoas`.
- `_criar_linha_seletor_sexo` passou a receber uma `StringVar` por linha e atualizar o visual do seletor correspondente via callback local.
- `coletar_pessoas_individuais` foi adicionado para coletar multiplas linhas preenchidas, ignorar linhas vazias e validar selecao explicita de sexo por pessoa.
- `iniciar_execucao_individual` passou a coletar uma lista de `CadastroPessoaEntrada` e encaminhar essa lista para `_executar_individual_thread`.
- `_executar_individual_thread` passou a aceitar `CadastroPessoaEntrada | list[CadastroPessoaEntrada]`, chamando `executar_cadastro_individual` para entrada unica legada e `executar_cadastro_pessoas` para lista.
- `_resumir_resultados` passou a aceitar `prefixo`, usado para diferenciar o resumo de lote do resumo de execucao unitaria com multiplas pessoas.
- `_bloquear_execucao` e `_liberar_execucao` passaram a atualizar tambem o estado da lista dinamica de pessoas durante a execucao.

**Observacoes:** Validado com testes unitarios/regressao especificos de criacao de pessoa AGHU e Ruff.
