**Sistema:** AGHU
**Data:** 2026-07-09
**Arquivo:** sistemas/aghu/criar_pessoa_aghu.py
**O que mudou:**
- `preencher_input` foi reduzida de 4 chamadas Playwright sequenciais (`wait_for(state="visible")` + `click()` + `fill("")` + `fill(valor)` condicional) para uma única `locator.fill(valor, timeout=timeout_ms)`. Pela doc oficial de actionability do Playwright, `fill()` já faz auto-wait de visibilidade/habilitação/editabilidade e já limpa o valor anterior antes de digitar, tornando as três chamadas anteriores redundantes. A função é usada ~11 vezes por pessoa cadastrada (nome, mãe, nascimento, RG, CPF, DDD, telefone, logradouro, bairro, CEP não cadastrado), então o corte remove overhead multiplicado por `slow_mo=500` quando `mostrar_browser=True`.
- `esconder_console_windows` agora envolve `ctypes.windll.kernel32.GetConsoleWindow()` e `ctypes.windll.user32.ShowWindow(...)` em `try/except Exception: pass`, no mesmo padrão aplicado a `criar_usuario_aghu.py` no commit `811257b`, evitando que uma falha nessa chamada de API do Windows derrube a automação antes de abrir o navegador.
**Observações:** Nenhum teste fixava o comportamento anterior de `preencher_input` ou `esconder_console_windows`; os 66 testes de `test_unit_criar_pessoa_aghu.py` + `test_regression_criar_pessoa_aghu.py` passaram sem necessidade de alteração. `ruff check` aprovado.
