**Sistema:** aghu
**Data:** 2026-07-09
**Arquivo:** sistemas/aghu/ui_concessor.py
**O que mudou:**
- A execução unitária deixou de aceitar um único par login/protocolo (`entry_login_alvo`/`entry_protocolo`) e passou a suportar de 1 a `MAX_USUARIOS_UNITARIOS` (5) usuários em lista dinâmica, reaproveitando o padrão adicionar/remover/reindexar de `ui_profissionais_unidade_cirurgica.py` através dos novos métodos `_adicionar_linha_usuario_concessao`, `_remover_linha_usuario_concessao` e `_atualizar_estado_linhas_usuarios_concessao`.
- Nova seção "ACESSO PADRÃO" (`_criar_secao_acesso_padrao`) concentra os `CTkOptionMenu` de escopo/categoria que valem por padrão para todos os usuários da lista; a seção antiga "Perfis da regra" foi renomeada para "Perfis da regra (Acesso padrão)" para deixar claro que a prévia reflete apenas o acesso padrão.
- Cada linha de usuário ganhou um `CTkCheckBox` "Acesso próprio" (`_on_toggle_acesso_proprio`) que revela um par de `CTkOptionMenu` de escopo/categoria específicos da linha (populados via `_on_escopo_proprio_changed`, mesma lógica de `_on_escopo_changed`) e um botão de reset (`_resetar_acesso_proprio`) ao lado do botão de remover, para descartar a customização com um clique.
- Novo método `_resolver_acesso_efetivo` decide, por linha, se o escopo/categoria efetivo vem do acesso próprio ou do acesso padrão; `_entradas_concessao_individuais` substitui `_entrada_concessao` e monta a lista de `ConcessaoPerfisEntrada`, ignorando linhas totalmente vazias e propagando erros de `validar_entrada` por linha.
- `iniciar_execucao_individual` e `_executar_thread` passaram a operar sobre uma lista de entradas: a thread agora chama `executar_concessoes_perfis` (função já existente no núcleo, usada anteriormente só pelo lote) em vez de `executar_concessao_perfis`; para 1 resultado mantém a mensagem `login: status - detalhes`, para mais de 1 usa `_resumir_resultados` com os novos parâmetros opcionais `prefixo`/`rotulo_total` (`"Execução unitária concluída"` / `"Total processado"`), reaproveitando a mesma contagem por status usada no relatório de lote.
- `_bloquear_execucao`/`_liberar_execucao` passaram a bloquear/liberar os controles da seção "Acesso padrão" (`option_escopo`, `option_categoria`) e delegam o bloqueio de cada linha de usuário (login, protocolo, checkbox, option menus próprios, botões de reset/remover) para `_atualizar_estado_linhas_usuarios_concessao`.
- Import de `executar_concessao_perfis` (singular) removido; `executar_concessoes_perfis` (plural) passou a ser importado de `concessor_aghu`.
**Observações:** Nenhuma alteração em `concessor_aghu.py`: a UI reaproveita `executar_concessoes_perfis` e `validar_entrada` já existentes no núcleo, sem duplicar regra de negócio. Testes de `testes/aghu/test_unit_ui_concessor.py` foram reescritos para cobrir adicionar/remover linha até o limite de 5, bloqueio de remoção da última linha, alternância do checkbox "Acesso próprio", resolução de acesso efetivo (padrão vs próprio) e bloqueio/liberação de todos os controles durante a execução.
